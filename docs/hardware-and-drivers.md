# 硬件与驱动适配

## 硬件资源

| 硬件 | 接口/系统入口 | 项目用途 |
| --- | --- | --- |
| LCD | framebuffer，当前 /dev/fb0 | Qt 图形界面 |
| FT5426 | I²C、input，当前 /dev/input/event1 | 触摸输入 |
| WM8960 | ALSA，当前声卡 0 | 喇叭音频输出 |
| AP3216C | I²C 字符设备 | 环境光、红外、接近检测 |
| ICM20608 | ECSPI3 字符设备 | 加速度、角速度及芯片内部温度 |
| Realtek USB 网卡 | USB、wlan0 | 网络天气与校时 |
| RTC | 当前 /dev/rtc0 | 硬件时间读写 |

设备编号取决于系统枚举结果，不应在更换内核后直接假定保持不变。

## 驱动来源与适配边界

drivers 目录保存 ap3216、icm20608、ft5426 和 realtek。Realtek 目录包含四种驱动源码，当前项目明确验证的是使用 8192cu 模块的网卡，其他驱动的验证情况需要分别记录。

AP3216C 和 ICM20608 使用字符设备接口。FT5426 替换 BSP 内核已有的对应实现。显示和声卡复用已有内核驱动，项目完成设备树适配及应用层联调。

源码集成、内核配置、驱动编译和设备树匹配是不同环节，缺少其中任意必要环节，都可能导致设备不能使用。详细集成方法见 ../drivers/README.md。

## I²C 设备共存

触摸、音频和传感器使用 I²C 并不意味着彼此冲突。是否冲突取决于总线、地址、引脚与资源配置。

同一 I²C 总线上可以连接多个不同地址的设备。AP3216C 使用 0x1e，设备树不应在同一总线上重复声明相同地址。曾出现的设备注册失败需要检查重复节点，不能仅凭日志判定驱动实现错误。

设备树控制器名称与 Linux i2c-N 编号不一定采用相同编号方式，应通过实际节点和设备对应关系确认。

## SPI 与片选

ICM20608 使用 ECSPI3，当前 Linux 中显示为 spi2.0。设备树配置 GPIO1_IO20 作为片选，并设置对应的 SPI 引脚复用。

GPIO 片选可以由 SPI 框架与控制器驱动配合管理，不需要传感器驱动额外重复申请该引脚。读取命令和返回数据之间需要遵循器件通信时序。

项目中曾因 UART2 与 ECSPI3 的引脚复用冲突导致芯片 ID 读取异常。修改相应节点解决冲突后，驱动通信恢复。后续维护应保留已经验证的引脚分配。

## 触摸与显示

显示驱动提供 framebuffer，触摸驱动提供 input 事件，两者分别工作。界面显示正常并不代表触摸已经正确映射；触摸可用也不代表字体配置完整。

Qt 启动环境应与实际屏幕和触摸节点一致。中文需要正确编码及包含中文字形的字体。

## 音频

WM8960 已注册为 ALSA 声卡。声音输出还需要打开 PCM 到左右输出混音器的路径，并设置合理的 Speaker 音量。

调试中使用过 Speaker 原始数值控制，但原始值不是百分比。Qt 页面上的百分比需要转换到声卡实际支持的音量范围。

项目已通过调整音频数据格式和播放配置完成正常播放。此前白噪声现象不能仅凭最终恢复播放，就归结为某一个确定的硬件故障。

## 无线通信

无线驱动负责识别设备和提供网络接口；wpa_supplicant 完成热点认证；DHCP 获取地址；路由决定出口；DNS 解析域名；curl 和 TLS 库完成 HTTPS 请求。

加载 8192cu.ko 并看到 wlan0，不代表已能访问互联网。需要继续完成认证、地址和网络访问确认。四种 Realtek 驱动不应仅为了目录中存在就全部同时加载。

## 时间与 RTC

Qt 时钟显示读取系统时间。联网校时用于修正系统时钟，RTC 用于硬件时间读写。RTC 是否能在完全断电后保持时间，取决于后备供电及实际硬件验证，当前文档不作未经验证的保证。

## 设备树交付范围

dts 目录当前保存最终 DTB。它可用于匹配环境下启动，但不能替代原始 DTS/DTSI 的维护价值。适配细节、源码恢复和部署注意事项见 ../dts/README.md。
