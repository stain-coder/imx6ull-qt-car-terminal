# 最终设备树 DTB

本目录保存车载终端最后实际使用的设备树二进制文件（.dtb），用于与对应的 i.MX6ULL 开发板、Linux 4.1.15 BSP 内核配套启动。

当前目录提供的是最终 DTB，不包含可直接维护的 DTS/DTSI 源码。因此，仓库可以提供已验证配置的部署文件，但仅依靠该目录不能完整重建原始设备树工程。

## 设备树的作用

设备树向内核描述板级硬件连接，例如外设是否启用、引脚复用、I²C 地址、SPI 片选、复位和中断 GPIO，以及屏幕时序、音频连接等信息。

设备树不包含驱动实现。设备树与匹配的内核驱动需要共同存在，硬件才能正常工作。

## 本项目涉及的适配

| 硬件 | 配置内容 |
| --- | --- |
| LCD | 显示接口、屏幕参数及相关引脚 |
| FT5426 | I²C 连接、触摸中断及复位等板级信息 |
| WM8960 | 音频连接、时钟及板级音频路由 |
| AP3216C | I²C 总线、0x1e 地址及驱动匹配信息 |
| ICM20608 | ECSPI3、GPIO1_IO20 片选和 SPI 引脚复用 |
| USB 无线网卡 | USB 主控制器及相关供电配置；网卡通过 USB 设备枚举匹配驱动 |

以上依据项目适配过程说明用途；具体属性和值以实际 DTB 和原始 BSP 为准。

本项目曾处理 ICM20608 与 UART2 引脚复用冲突。后续修改设备树时，需要检查相关引脚没有同时分配给两个启用的外设。

## 如何使用

1. 保留当前可启动的内核和 DTB 作为备份。
2. 将本目录的 DTB 复制到实际启动流程读取的位置。
3. 检查 U-Boot 最终加载的文件名、路径和内存地址，确认它加载的是新的 DTB。
4. 使用与本项目驱动集成状态一致的内核启动。
5. 根据启动日志确认触摸、音频、显示和传感器是否正确匹配。

如果使用 TFTP 启动，DTB 应放入 TFTP 服务目录，并由启动命令加载；如果从存储介质启动，则更新对应启动分区。单纯复制到 NFS 根文件系统并不表示 U-Boot 会使用它。

本文不固定加载地址或提供覆盖式启动命令，因为这些参数取决于实际 U-Boot 环境。

## DTB 与源码

DTS 是主要设备树源码，DTSI 是被引用的公共描述，DTB 是编译后的二进制结果。后续维护建议同时保存实际使用的 DTS、修改过的 DTSI 以及 BSP 版本信息。

开发机安装 dtc 后，可以反编译 DTB，辅助查看最终属性：

~~~sh
dtc -I dtb -O dts -o board-decoded.dts 实际设备树文件.dtb
~~~

反编译结果不等同于原始源码，不能恢复原有注释、宏和 include 组织关系。它适合检查配置，不应当作原始设备树工程的完整替代。
