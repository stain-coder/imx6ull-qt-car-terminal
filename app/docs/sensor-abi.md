# Qt 与字符设备驱动的数据约定

仅适用于本次已修改并由用户验证的字符驱动，不能直接用于其他网上版本或 IIO 驱动。

| 设备 | 每次 read 长度 | 数据类型与顺序 |
|---|---:|---|
| /dev/ap3216c | 6 字节 | 本机字节序 uint16_t[IR, ALS, PS] |
| /dev/icm20608 | 28 字节 | 本机字节序 int32_t[GX,GY,GZ,AX,AY,AZ,Traw] |

目标 ARM 是小端。内核已完成芯片寄存器高低字节合并，Qt 不再次交换字节。
每次只调用一次 read，必须等于完整帧长；不能将两次采样拼成一帧。
旧教学驱动若成功时返回0，Qt会提示帧长错误，必须使用已修正 read 返回长度的版本。

ICM20608 驱动配置 GYRO_CONFIG=0x18（±2000°/s），ACCEL_CONFIG=0x18（±16g）。
本应用换算：加速度原始值/2048.0 -> g；角速度原始值/16.4 -> °/s。
更改驱动量程必须同步修改 sensors.cpp，不要只改显示单位。
AP3216C EOVERFLOW 表示本帧无效，三项均清空；本版不把原始 ALS 标作 lux。

SensorThread 在后台执行 open/read/close，信号以 QueuedConnection 送至 GUI 更新 QLabel。
句柄保持打开，避免反复初始化和争用；错误后按周期重试打开。
O_NONBLOCK 不保证旧自编驱动真正非阻塞；如果底层总线调用永久挂起，GUI仍能响应，但正常退出等待线程时可能被阻塞，需要修复内核驱动超时。应用不强行终止正在执行内核读操作的线程。
超过3秒没有采样信号时，GUI清空旧数据显示超时。当前两传感器共用一个采集线程，一颗永久阻塞也会影响另一颗的更新。

参考：Qt QThread 文档 https://doc.qt.io/qt-5/qthread.html
