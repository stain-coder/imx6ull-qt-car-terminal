# 驱动与内核适配说明

本目录保存 i.MX6ULL 车载终端项目使用的传感器、触摸屏和 Realtek 无线网卡驱动。目标内核为 Linux 4.1.15，用户空间由 Buildroot 构建，Qt 应用负责音乐播放、传感器数据显示、天气查询及触摸交互。

这些驱动需要集成到开发板实际使用的内核源码中，并完成配置和编译。将源码放进 GitHub 的 `drivers/` 目录，仅用于归档与交付，不会自动使驱动生效。

## 1. 目录内容

| 目录 | 硬件及接口 | 在项目中的用途 | 集成方式 |
| --- | --- | --- | --- |
| `ap3216/` | AP3216C，I²C | 采集环境光、红外和接近检测数据 | 添加到内核源码，配置编译入口及设备树 |
| `icm20608/` | ICM20608，SPI | 采集三轴加速度、三轴角速度及芯片内部温度数据 | 添加到内核源码，配置编译入口及设备树 |
| `ft5426/` | FT5426，I²C | 提供触摸输入，支持 Qt 页面及控件操作 | 替换 BSP 内核中原有的对应触摸驱动，并检查设备树 |
| `realtek/` | 四种 Realtek 网卡驱动源码 | 为匹配的无线网卡提供驱动支持 | 按各源码的集成方式接入内核构建，按实际网卡选择启用 |

Realtek 四种驱动的名称、支持的 USB ID 和配置项应以各子目录实际源码为准。本项目已验证使用 `8192cu.ko` 的 USB 无线网卡；不能由此认为其他三个驱动也已经完成实机验证。

AP3216C 不提供环境温度和湿度测量。ICM20608 的温度是芯片内部温度，不等同于车内空气温度；天气页面的温湿度来自网络天气服务。

## 2. 本项目的驱动工作范围

本项目包含传感器驱动集成、触摸驱动替换、无线网卡驱动移植以及设备树适配。

以下功能复用开发板 BSP 内核已有的驱动，不在本目录重复提供：

| 功能 | 使用方式 |
| --- | --- |
| WM8960 音频 | 复用内核已有的声卡及相关音频驱动，适配设备树，并在用户空间配置 ALSA 播放通路和音量 |
| LCD 显示 | 复用内核已有的显示驱动，通过设备树适配屏幕接口及显示参数，向应用提供 framebuffer |

因此，项目中的音频和显示工作应描述为“基于已有驱动完成设备树适配与功能验证”，不应描述为从零编写声卡或 LCD 控制器驱动。

## 3. 集成到 Linux 4.1.15

### 3.1 确认内核源码和设备树

使用当前开发板已经验证可启动的 BSP 内核源码。保留原有内核配置，并备份准备替换的驱动文件。

仓库内的目录用于组织项目资料，不要求与内核源码中的目录一一对应。实际放置位置、配置项名称和编译目标，应与所使用的 BSP 及各驱动源码保持一致。

### 3.2 添加 AP3216C 和 ICM20608 驱动

1. 将驱动源文件及其依赖的头文件复制到内核源码中。
2. 如果采用本项目的字符设备实现，可以沿用原先已经验证的 `drivers/misc/` 集成方式。
3. 在对应目录的 `Kconfig` 中添加配置项，在 `Makefile` 中添加编译规则；已有条目不要重复添加。
4. 在内核配置中启用相应驱动。
5. 在设备树中配置 I²C 或 SPI 设备节点，确保 `compatible` 与驱动的匹配表一致。

其中，`Kconfig` 用于定义配置菜单及依赖关系，`Makefile` 用于将配置选择关联到实际编译的源文件。

AP3216C 所在 I²C 总线需要启用，设备地址为 `0x1e`。同一条总线上不要重复创建相同地址的设备节点，否则会发生设备注册冲突。

本项目的 ICM20608 使用 ECSPI3，片选为 GPIO1_IO20。设备树需要配置 SPI 引脚复用、片选、设备序号和通信频率。相关引脚与 UART2 存在复用关系，应确认没有被 UART2 同时占用。片选控制方式应保持与已验证驱动和 SPI 控制器配置一致，避免重复申请或控制同一个 GPIO。

### 3.3 替换 FT5426 驱动

1. 在实际 BSP 内核中找到原有 FT5426 对应驱动文件及其编译入口。
2. 备份原文件，再用本项目已验证的版本替换。
3. 如果文件名或配置项发生变化，同步修改对应的 `Makefile` 和 `Kconfig`；名称不变且原入口有效时，无需重复添加。
4. 检查设备树中的 I²C 地址、中断、复位及引脚配置是否与驱动一致。
5. 避免同时启用两个驱动去匹配同一个触摸设备。

FT5426 通过 Linux input 子系统向 Qt 提供触摸事件。本项目当前使用 `/dev/input/event1`，但该编号可能随设备注册顺序变化，部署时应检查实际设备名称与事件节点的对应关系。

### 3.4 集成 Realtek 无线网卡驱动

`realtek/` 收录四种驱动，作为不同无线网卡的适配源码。每种驱动都需要具备有效的内核编译入口，但实际固件不必同时启用或加载全部驱动。

1. 根据实际 USB 网卡的设备 ID，确认匹配的驱动。
2. 按该驱动源码的组织方式，接入内核网络驱动目录的 `Kconfig`、`Makefile` 及所需依赖。
3. 根据需要选择编入内核或编译成模块。
4. 确认没有其他已启用驱动与其争用同一设备。
5. 编译后在开发板确认 USB 设备识别、驱动绑定及无线接口创建情况。

USB 无线网卡通常通过 USB 枚举与设备 ID 匹配，不需要像 I²C 传感器一样为每个网卡编写设备树子节点；开发板 USB 控制器及相关供电仍需正确配置。

本项目当前验证的模块加载方式为：

```sh
insmod /lib/modules/4.1.15/8192cu.ko
```

该命令仅适用于模块实际位于上述路径、与运行内核匹配且依赖已满足的情况。目标系统使用 `insmod` 加载模块；它不会自动查找和加载依赖模块。

驱动加载成功只代表具备无线通信的基础能力。连接热点、获取 IP 地址、DNS 解析和 HTTPS 请求，还分别需要用户空间的认证、网络配置及请求工具配合完成。

## 4. 编译与部署说明

驱动可以选择两种构建方式：

| 方式 | 配置值 | 部署要求 |
| --- | --- | --- |
| 编入内核 | `y` | 更新内核镜像；设备树有修改时，同时更新 DTB |
| 可加载模块 | `m` | 部署生成的 `.ko`；有设备树修改时更新 DTB，再加载模块 |

模块必须使用与目标内核匹配的源码、配置及构建产物编译。不能仅因为版本字符串都是 `4.1.15` 就认为模块一定兼容。

内核和驱动继续使用项目已经验证的内核交叉编译环境。Buildroot 生成的工具链用于本项目用户空间和 Qt 应用构建，两套构建环境应分别指定，避免混用。

设备树修改不会因为复制 `.dts` 文件到根文件系统就生效，需要重新编译并让启动流程加载新的 DTB。内置驱动修改则需要重新构建并启动新的内核镜像。

## 5. 驱动与 Qt 应用的联系

| 功能 | 内核侧提供的接口 | 用户空间使用方式 |
| --- | --- | --- |
| AP3216C | 字符设备节点 | 应用打开设备并读取传感器数据，更新页面 |
| ICM20608 | 字符设备节点 | 应用读取原始运动数据，按驱动量程换算并显示 |
| FT5426 | input 事件设备 | Qt 输入插件读取触摸事件，响应按钮、滑块及页面操作 |
| Realtek 无线网卡 | 网络接口，如 `wlan0` | 配合 `wpa_supplicant`、DHCP 和路由配置访问网络 |
| WM8960 | ALSA 声音设备 | 用户空间通过 ALSA 接口播放音频并设置音量 |
| LCD | framebuffer，如 `/dev/fb0` | Qt 使用 linuxfb 平台插件输出画面 |

传感器驱动与应用必须对设备节点名称、读取长度、字段顺序、数据类型及单位采用一致约定。修改字符设备的数据格式时，应同步修改测试程序和 Qt 读取代码。

## 6. 功能验证

建议先使用独立测试程序验证驱动，再启动 Qt 应用进行联合验证。

| 模块 | 验证内容 |
| --- | --- |
| AP3216C | 设备正常匹配，测试程序读取成功；改变照明或靠近传感器时，相应读数变化 |
| ICM20608 | 芯片 ID 读取正常；静止、转动或改变姿态时，加速度和角速度读数符合预期 |
| FT5426 | 触摸事件正常上报，Qt 点击位置对应正确，滑动控件可以连续操作 |
| Realtek | 网卡识别成功，热点认证完成，获取地址，并验证网关、外网和域名访问 |
| 音频与显示 | 音频正常播放；界面、字体和触摸功能在联合运行时正常 |

可使用以下命令辅助检查，具体工具是否可用取决于根文件系统配置：

```sh
# 查看传感器、触摸及无线驱动相关日志
dmesg | grep -i -E 'ap3216|icm20608|ft5|8192|realtek'

# 查看 input 设备名称及对应事件节点
cat /proc/bus/input/devices

# 查看当前加载的模块，不包含已经编入内核的驱动
lsmod

# 查看网络接口
ifconfig -a

# 查看 ALSA 播放设备
aplay -l
```

实际测试现象、截图和结果应记录在项目测试文档中。四种 Realtek 驱动应分别标明“已验证”或“未验证”，不要把收录源码等同于功能验证完成。

## 7. 源码来源与维护

本目录包含项目适配使用的驱动源码。各文件应保留其原有版权声明、作者信息和许可证说明。对于基于已有代码完成的修改，可增加 `gongting` 的适配维护说明，并记录具体修改内容；不能将原作者的代码全部标记为独立原创。

本项目维护与集成：gongting。

各驱动适用的许可证以其源码及随附许可文件为准。若仓库根目录提供统一许可证说明，应明确第三方驱动仍遵循各自原有许可。
