# 构建配置说明

本目录保存车载终端使用的构建配置，便于查看软件包选择和恢复开发环境。网络连接参数由部署者在目标系统中设置，本仓库不提供 network 子目录，也不保存实际 Wi-Fi 密码。

## 配置文件

下面使用建议文件名说明各配置的来源。仓库内实际文件名不同时，请使用对应文件，不要仅凭文件名判断配置类型。

| 建议名称 | 原始位置 | 作用 |
| --- | --- | --- |
| buildroot.config | Buildroot 的 output-car/.config | 保存目标架构、工具链、软件包及根文件系统选项 |
| busybox.config | output-car/build/busybox-版本号/.config | 保存 BusyBox 命令及功能选项 |
| kernel.config | Linux 源码根目录的 .config | 保存内核功能与驱动编译选项 |

本项目目标内核为 Linux 4.1.15，Buildroot 使用 2025.02.17，ARM Qt 使用 5.15.18。配置应与相应源码版本配套使用；BSP 补丁、驱动源码和设备树不包含在这些配置文件中。

## Buildroot 配置

完整 .config 记录当前构建选择；它与通过 savedefconfig 导出的精简 defconfig 不是同一种文件，不应仅改文件名就认为完成转换。

恢复时，建议在新的输出目录操作，不覆盖现有 output-car：

1. 在 Buildroot 源码目录创建新的输出目录。
2. 将本目录的 Buildroot 配置复制为新输出目录下的 .config。
3. 使用相同 O=输出目录执行 olddefconfig，再进入 menuconfig 检查配置。
4. 检查配置中的本机绝对路径、下载位置和自定义文件路径是否仍有效。
5. 确认后构建根文件系统和用户空间工具链。

olddefconfig 会根据当前源码补充默认配置，并不能保证跨版本得到完全相同的结果。复现应优先使用本项目相同版本。

## BusyBox 配置

BusyBox 将多个常用命令集成在一个程序中。其配置决定是否包含 udhcpc、ntpd 等功能，与 Buildroot 选择哪些独立软件包不同。

恢复时，应在 Buildroot 的 BusyBox 设置中将自定义配置文件指向本仓库保存的 busybox.config，再按该 Buildroot 版本的配置流程重新构建 BusyBox。仅把文件放进仓库，不会自动参与构建。

本项目调试过程中还使用过单独部署的 BusyBox 程序提供网络校时功能。目标系统实际调用的 BusyBox 二进制必须与预期配置一致；更新配置文件本身不会改变已部署程序。

## 内核配置

kernel.config 应恢复到对应 BSP 内核源码中，并检查新增驱动的 Kconfig、Makefile 及源文件已经集成，再重新构建。

配置为 y 的驱动编入内核，配置为 m 的驱动生成模块。模块需要与运行中的内核构建匹配，不能使用 Buildroot 用户空间配置替代内核配置。

## 应用配置与本目录的区别

Qt 工程中的 config/car.ini 是应用运行参数，涉及设备路径、音乐目录和天气参数；本目录保存的是系统构建配置。两类配置应分别保留。

配置文件可能含有开发机路径。上传前可去除不必要的个人路径，但修改后应检查其引用关系，避免破坏构建。
